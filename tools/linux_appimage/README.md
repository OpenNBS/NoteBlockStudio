# Note Block Studio AppImage integration

This directory provides the `AppRun` and desktop metadata needed to associate
both `.nbs` files and `nbs://` URLs with a movable Note Block Studio AppImage.
The directory is self-contained, so it can be copied to a Linux remote-build
host without the rest of the source repository.

## Prepare an AppDir

Run the preparation step after the normal AppImage tooling has created the
AppDir and its `AppRun`:

```sh
tools/linux_appimage/prepare_appdir.sh /path/to/NoteBlockStudio.AppDir
```

The existing `AppRun` is retained as `AppRun.nbs-original`, so any library-path
or environment setup generated by the packaging tool continues to run after
the NBS desktop registration. Any other root-level desktop entry is preserved
under `usr/lib/opennbs/original-desktop-entries`; the AppDir root keeps the
single desktop entry required for Note Block Studio.

If `usr/bin/assets/ffmpeg` or `usr/bin/assets/ffprobe` is present, the preparation
step also marks it executable.

If the AppDir has no `AppRun`, provide the GameMaker executable's path relative
to the AppDir explicitly:

```sh
tools/linux_appimage/prepare_appdir.sh \
  /path/to/NoteBlockStudio.AppDir \
  "usr/lib/opennbs/Note Block Studio"
```

The resulting AppDir can then be passed to `appimagetool`.

## Runtime behavior

On every AppImage launch, `AppRun` uses the AppImage-provided `$APPIMAGE` value
to update two per-user desktop entries:

- `org.opennbs.onbs.desktop` opens `audio/vnd.opennbs.nbs` files in the editor.
- `org.opennbs.onbs-protocol.desktop` opens `nbs://` URLs with
  `--protocol-launcher`, which selects player mode.

The MIME definition is installed for the `*.nbs` glob, and `xdg-mime` is used
to establish defaults when no different user-selected handler is present.

After an AppImage is moved, launching it once from its new location refreshes
both desktop entries. A desktop cannot discover an arbitrarily moved AppImage
before that first launch because its previous executable path is stale.
